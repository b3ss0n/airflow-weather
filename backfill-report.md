# Загрузка года истории

Загрузил погоду для четырёх городов за 365 суток UTC, с 17.11.2025 по 16.11.2026 включительно. PostgreSQL подтвердил полное покрытие.

| Таблица | Строк в базе |
|---|---:|
| `raw_weather` | 1 460 |
| `hourly_weather` | 35 040 |
| `daily_stats` | 1 460 |

Для каждой пары «город — дата» проверил 24 уникальных часа UTC и все пять дневных показателей. Их значения совпали с пересчётом по почасовым данным. Пропусков за выбранный период не было.

## Как загружал

Использовал встроенный backfill Airflow и тот же DAG, что и для обычной ежедневной загрузки. Сначала проверил даты через `--dry-run`, затем прогнал пробные сутки. Основная команда запускалась с `--reprocess-behavior failed`, поэтому Airflow повторял упавшие интервалы и использовал данные из уже успешных запусков. За четыре даты, которые успели загрузить до появления агрегации, отдельно пересчитал 16 дневных сводок из готовых почасовых данных.

## Что пришлось исправить по ходу загрузки

- Docker Desktop дважды переставал отвечать. Очередь Airflow сохранилась в PostgreSQL и продолжилась после перезапуска. При чтении каталога DAG с Windows-диска Airflow также получал `Cannot allocate memory`. На время загрузки перенёс копию файлов DAG в Linux-том Docker и ограничил параллелизм.
- Запросы к Open-Meteo периодически обрывались по TLS. Временная копия DAG использовала `httpx` с резервным запросом через `curl`. Шесть дат после исчерпания встроенных повторов запустил ещё раз через Airflow. Все шесть завершились успешно.
- По итогам вернул исходную конфигурацию и удалил временный том. Повторная проверка PostgreSQL подтвердила те же числа.
